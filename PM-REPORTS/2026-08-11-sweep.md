## Summary

Two defects would each have broken sign-up night on their own. The name validator **rejected the exact format the page tells members to use** ("Ed R."), and returned an error repeating that same instruction. Separately, re-clicking "Open sign-up" on a live session **archived and deleted everyone already signed up**, with the date box helpfully pre-filled with that very session. Both fixed. A third, the organiser's cancel token being guessable from public data, was mine, introduced an hour before the sweep found it.

## Fixed in this sweep

**FM-002.** `NAME_PATTERN` had no full stop, so "Ed R." and "Sarah J." were refused, while the placeholder said `e.g. Ed R.` and the site publishes "Sarah J.". The page then showed canned copy telling the member to enter a first name and last initial. Allowing full stops outright would have admitted `example.com`, since it contains no digits, so validation is now per word: each word is either a name word or a single-letter initial. Verified: "Ed R.", "Sarah J.", "Aoife O'Brien", "Anne-Marie Smith-Jones", "Renée Dupont" accepted; "example.com", "John Smith.", "buy.now.cheap", "Ed 123" rejected. The page now prefers the server's specific message over the canned line.

**FM-003.** `open` archived and `del`d unconditionally, and `prefillAdmin` fills the date box with the live session's date. Re-opening the same date is now treated as an edit: label and opening time update, the queue is left alone.

**FM-004.** Self-inflicted. The organiser's token was `organiser:${useDate}` and `date` is returned in every public GET, so `POST {action:'leave', token:'organiser:2026-08-13'}` removed whoever was running the session. Now `randomUUID()`.

**FM-005.** Nothing ever expired a session, so Monday's list read "Open now" on Wednesday and a tap joined the waiting list for a game already played. `meta.endsAt` is now stored at open time from the schedule's end hour, `viewModel` reports `closed` past it, and `openState` refuses joins.

**FM-006.** Player names went into `innerHTML` unescaped at five sinks in `pairings.html`. The reachable route is the paste box: a member sets a crafted "name" in WhatsApp, the organiser pastes the list, and it executes for every member viewing the board and is committed to the public repo. Reproduced firing, then escaped all five. `box-league.html` shares the pattern but `submit_score` validates names against the roster, so it is not remotely reachable.

**FM-007, FM-009, FM-010.** Per-IP limits in Redis (`hitRateLimit`): 8 joins per hour, 10 admin password attempts per 15 minutes. The anonymous GET is cached 5 seconds and polling dropped from 10s to 25s, which together cut the command spend on a busy evening by roughly an order of magnitude.

**FM-008.** Organiser name is validated before anything is deleted, and the name actually seated is recorded, so the "Running today" tag cannot point at nobody.

## Still open, with recommendations

**FM-011, timezone.** `defaultOpensAt` builds 8 PM in the server's zone, which is UTC on Vercel, so it lands at 9 PM in Manchester from late March to late October. Limited blast radius, because the admin form always sends an explicit time. Worth fixing before anyone relies on the default. Note the existing harness cannot catch it: it asserts `getHours() === 20`, which reads back in the runner's own zone and passes anywhere.

**FM-012, archive deadlock.** If GitHub is down at 7:55 PM, neither `open` nor `reset` will clear the list, so the club cannot start sign-up at all. Recommend a `force` flag behind a second confirmation.

**FM-013, overlapping refreshes.** Three timers can have requests in flight at once and the last to land wins, so a slow `pending` can overwrite a fresh `open`. Recommend a request sequence number.

**FM-014, published first names.** `shortenName` guarantees the structure but the first word is up to 30 attacker-chosen letters, published on a search-indexed page and then committed permanently to a public repo where admin removal cannot reach it. Recommend a small blocklist and skipping admin-removed entries at archive time.

**FM-015, homoglyphs.** Parked. Needs a deliberate attacker with Cyrillic lookalikes; a real member will never trigger it.

## Observations

- `EVAL` ships the whole Lua body on every join rather than `EVALSHA`. Bandwidth only.
- `open` does `del` then `hset` non-atomically; a join landing between them would seat someone at position 1 of the next session. Needs simultaneity with an admin button press.
- Admin actions have no busy guard, unlike join, so a double-click fires two opens. They converge, but it makes FM-003 easier to trigger by accident.
- The "storage not configured" 500 carries a genuinely useful hint that the page discards in favour of "Check your connection".

## Verified clean

Cancel tokens never appear in any response or in the archive; browser tokens are 128 bits of `crypto.getRandomValues`. The Lua join script is atomic and cannot issue a position twice or be raced past its cap. A missing `ADMIN_PASSWORD` refuses rather than bypasses. `validateName` rejects RLO characters, combining marks and pure whitespace. `submit_score` validates players against the roster.

Regression cover: `test-signup.html` now at **246 assertions, all passing**, including the full-stop cases and session closing.
